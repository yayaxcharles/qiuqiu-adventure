## 2. 斜上 45 度丟（決定 1）

### 白話
現在只能朝前、朝正上方、空中朝下、蹲著低丟。加一個「斜上」：**按住 ↑ 再加 ← 或 →** 就往斜上 45 度丟；只按 ↑ 還是正上方。手裏劍、九種撿來的忍具、爆裂符和焙烙玉都一樣。站著、跑著、空中都能斜丟。

### 做法（給實作的人）
- `src/entities.ts`：`Aim` 從 `'fwd' | 'up' | 'down' | 'low'` 加上 `'diag'`（斜上）。
- `src/player.ts` 的 `attack()`：瞄準判斷改成
  `f.up && dir !== 0 → 'diag'`、`f.up → 'up'`、其餘照舊。`HAND` 加 `diag: { x: 92, y: -168 }`（朝前和朝上之間，實際值等斜丟動作圖出來用 `release` 那一格量）。
- `src/world.ts` 的 `fireWeapon()`：方向向量 `diag`＝(facing×0.707, −0.707)。各忍具：
  | 忍具 | 斜上怎麼處理 |
  |---|---|
  | 手裏劍、棒手裏劍 H、風魔 R、紙鶴 C、吹箭 B | 照向量飛，`rot` 已經用 atan2 算，自動轉向 |
  | 撒菱 S | 扇形中心角轉到 −45 度 |
  | 毛球 D | 斜上初速，照舊受重力彈跳 |
  | 鼠火 I（貼地跑） | 斜上＝朝前（貼地的沒有斜的意思） |
  | 火藥竹筒 F、鎖鎌 L（黏在手上的長條） | 長條轉 45 度。打中判定（`shotHits`）現在是「朝前／朝上／朝下」三種長方形，斜的改成沿線放 5 個小圓；畫法 `ctx.rotate(-π/4 × facing)` |
- 副武器 `throwSub()`：現在只有「朝前」（vx 430, vy −560）和「↑」（vx 220, vy −820）。改成
  `↑ 加方向 → 斜上：vx 330, vy −760`；只按 ↑ 還是原本的高拋；煙玉不變。
- 自動換手：斜上時 `meleeTarget` 不觸發揮爪（跟現在按 ↑ 一樣）。
- **動作圖**：新生「站著斜上丟」和「跑步斜上丟」兩支（第 8 節）。還沒生好之前先用 `throwup`（朝上丟）的動作，**但沒生好不算完成**。
- 手機方向盤（`src/touch.ts`）：現在 `up: dy < −0.5`、左右有死區，斜上本來就會同時亮 ↑ 和 →，要改的是分區：改成八方向、每區 45 度，讓「幾乎正上」不會誤判成斜上（正上 ±22.5 度才算正上）。

### 驗收
- 單元測試：`diag` 的飛行方向、各忍具斜丟有打中判定、副武器斜上落點在朝前和朝上之間。
- 錄影：第一關烏鴉段、第二關燈籠鬼段各斜丟 10 秒。

## 3. 手裏劍削弱（決定 2）

### 白話
現在手裏劍一秒能丟快 8 枚、一枚飛 920 像素（快要整個畫面寬），所以魔王很快倒、一路狂按就過。改成：飛慢一點、飛近一點、丟慢一點、畫面上同時最多 3 枚（越南大戰手槍的感覺）。傷害不動。

### 現在 vs 建議

| 數字（`src/weapons.ts`、`src/world.ts`） | 現在 | 建議 | 效果 |
|---|---|---|---|
| 飛行速度 | 1150 像素／秒 | **760** | 看得到它飛過去 |
| 飛多久 | 0.8 秒（射程 920） | **1.0 秒（射程 760）** | 約畫面六成寬 |
| 連丟間隔 `cooldown` | 0.13 秒（每秒 7.7 枚） | **0.22 秒（每秒 4.5 枚）** | |
| 同時在畫面上 | 不限 | **最多 3 枚**（第 4 枚按了不出手） | 貼近打比較快，鼓勵走近、用爪 |
| 傷害 | 10 | 10（不動） | |
| 每秒最大傷害 | 約 77 | 約 45（−42%） | |

其他撿來的忍具這次不動（使用者只說手裏劍）；但削完之後撿到忍具會顯得更強，這是想要的效果。

### 分兩步量，不要一次到底
- **A 步**：只改速度、射程、同時 3 枚。
- **B 步**：再加連丟間隔 0.22。
- 每步都跑第 9.1 節的平衡報表（三關 × 5 種子），跟 `docs/平衡基準_v1.csv` 比：

| 指標 | 希望的範圍 |
|---|---|
| 每關破關時間 | 比原本多 10～25%（原本自動玩約 205／244／257 秒） |
| 每場魔王戰時間（魔王出場到倒下） | 多 25～50% |
| 倒下次數 | 每關最多多 3 次；三關都要打得通 |
| 被什麼打到（`hurtBy`） | 看有沒有哪一種突然暴增（例如近身小兵，代表「丟不死只好靠近」太難） |

超出範圍就調中間值（例如間隔 0.18）。數字只是自動玩的，**最後以你玩三分鐘覺得「太弱／剛好」為準**。

## 4. 揮爪修正（決定 3）

### 白話
現在的問題是：敵人走到 150 像素內才出爪，但出爪要 0.37 秒才打到，這段時間敵人已經撞上來了。改四件事：**爪子搆得更遠、出爪更快、出爪那一下被「碰到」不扣血、打中小兵把牠推開。** 被子彈或敵人的武器打到還是會扣血，不是無敵。

### 數字（`src/player.ts` 的 `CLAW`、`src/world.ts` 的 `meleeTarget`）

| 項目 | 現在 | 建議 |
|---|---|---|
| 觸發揮爪的距離（`meleeTarget` 區域） | 身體前方 10～150 | **10～190** |
| 打中範圍（`CLAW.reach`） | 10～150，高 170 | **0～210，高 190** |
| 出爪時間 | 從第 0 格播、第 16 格打中、1.8 倍速 → 0.37 秒 | **從第 6 格開始播、打中前 2.4 倍速 → 0.17 秒** |
| 打中判定視窗（`CLAW.win`） | 打中前 1 格～後 3 格 | **前 2 格～後 4 格** |
| 出爪護身 | 無 | **出爪開始到打中後第 4 格（約 0.25 秒）：被敵人身體碰到不扣血**（`bodyHarm` 那條跳過）；子彈、敵人出招的攻擊判定（`harm`）照樣扣 |
| 擊退 | 無 | 打中小兵（非魔王、非重甲）往後推 80 像素、僵住 0.25 秒；鐵羅漢等重的不推 |

- 注意：全身是刺的橘皮大王二階還是不能出爪（現在的規則保留）。
- 另外建議（不急）：出爪打中後給自己 0.15 秒無敵，避免同時兩隻夾擊。先不做，看數字再說。

### 怎麼驗證
- 在 `hurtPlayer` 的事件記錄加一欄「當時在做什麼」（`act`），平衡報表多一列「揮爪中被碰到次數」。目標：**接近 0**（原本要先量出來）。
- 單元測試：鼠兵以最快速度衝過來，按攻擊，確認打中在牠碰到身體之前。

## 5. 新動作：翻滾、二段跳、蹬牆跳、攀爬（決定 4、5）

### 5.1 翻滾

**白話**：地上按「衝刺鍵」（鍵盤 I，手機一顆新按鈕「滾」）＝往前滾一圈。滾的時候身體變矮、大約 0.3 秒內碰到敵人和子彈都不會扣血，可以直接穿過去（包含穿過魔王身體）。空中按同一顆鍵還是原本的空中衝刺。

| 數字 | 建議 |
|---|---|
| 滾多久 | 0.40 秒 |
| 滾多遠 | 約 280 像素（速度 700） |
| 無敵 | 開始後 0.04～0.34 秒 |
| 身體判定高度 | 150 → 84（低的苦無還是會碰到，但無敵期間不扣） |
| 冷卻 | 滾完後 0.25 秒才能再滾 |
| 可以取消 | 最後 0.08 秒可以接跳或丟 |
| 滾出平台邊緣 | 照速度飛出去、變成往下掉 |
| 撞到牆 | 停在牆前、翻滾提早結束 |
| 魔王碰撞推開 | 翻滾中不推（才穿得過去） |

- 程式：`player.ts` 新增動作狀態 `'roll'`，跟現有 `'dash'`（760 速、無敵 0.25 秒）同一套寫法，`tryStart('dash')` 在地上時改走翻滾。`box()` 翻滾時變矮。`world.ts` 魔王推開那段（`e.boss && ... overlap`）翻滾中跳過。
- 風險：翻滾穿魔王可能讓魔王戰太簡單 → 平衡報表看魔王戰時間，必要時魔王出招的攻擊判定照扣（無敵只擋身體碰撞與子彈）。

### 5.2 二段跳

**白話**：跳起來之後在空中再按一次跳，會再往上翻一次。一次落地前只能一次。

| 數字 | 建議 |
|---|---|
| 第二跳初速 | 820（第一跳 960） |
| 高度 | 第一跳最高約 177 像素；第二跳再約 129 → 最高約 300 |
| 次數 | 落地、蹬牆、抓到藤蔓時補回 |
| 走出平台邊緣沒跳就掉 | 還能用那一次空中跳（土狼時間內按＝算第一跳） |
| 放開跳鍵截斷 | 第二跳也適用（`jumpCut`） |

- 程式：`physics.ts` 的 `Body` 加 `airJumps`；`stepBody` 在不在地上、土狼時間用完、`jumpPressed` 時用掉一次。
- 影響舊關卡：屋頂前的踏腳木台變成可有可無；升降機井的 200 高牆（第三關 15,200）二段跳就上得去 → **不改牆高，讓它變成「會二段跳的人的捷徑」**，自動玩還是搭升降台（測試兩種都要過）。

### 5.3 蹬牆跳（貼牆滑下＋蹬牆跳）

**白話**：在空中貼著一面高牆，會慢慢滑下來；這時按跳，會往反方向蹬出去再往上。兩面牆夾著的窄縫，可以左右左右一路蹬上去。

| 數字 | 建議 |
|---|---|
| 哪些牆能蹬 | 地形的垂直落差高 ≥ 120 的那一面，加上新的「實心方塊」（見下） |
| 貼牆條件 | 在空中、往下掉中、按著朝牆的方向、離牆 4 像素內 |
| 滑下速度上限 | 1500 → **240** |
| 蹬出去 | 水平 560（離開牆的方向）、往上 900 |
| 蹬完鎖方向 | 0.15 秒內按反方向無效（不然會馬上黏回牆） |
| 離牆寬限 | 離開牆 0.1 秒內按跳還算蹬牆（跟土狼時間一樣的道理） |
| 補回 | 蹬牆後二段跳補回 |
| 夾縫寬度（關卡設計用） | 兩面牆距離 200～320 |

- **物理要加的東西（最大的程式改動）**：現在的地形是「每個 x 一個地面高度」（一條折線），畫不出「兩面牆夾一條縫」或「懸空的岩塊」。新增一種關卡物件「實心方塊」`solids: { x, y, w, h, look }`：上面可以站、左右是牆、下面是天花板（撞頭）。`stepBody` 回傳多一個 `wallDir`（左牆／右牆／沒有）。
- 現有的斷崖（例如第一關 6,900 往下 140 那面）也會變成能蹬的牆；這是好事，不另外擋。

### 5.4 攀爬（藤蔓、梯子、鐵鍊）

**白話**：走到藤蔓或梯子前面按 ↑ 就抓上去，↑↓ 上下爬，按跳往旁邊跳開，爬到頂會自己翻上去。

| 數字 | 建議 |
|---|---|
| 關卡物件 | `climbs: { x, top, bottom, look: 'vine' \| 'ladder' \| 'chain' }`，寬 60 |

| 攀爬中能不能丟 | 先允許朝前丟（用空中丟的動作），**錄影看起來怪就改成不能丟** |
| 被打 | 從藤蔓上被打下來 |

### 5.5 坡（決定 5）

**白話**：現在已經有坡，但都很緩（大約 10 度）。第二版加 20～30 度的陡坡，上坡跑慢一點、下坡快一點；敵人、道具、子彈在坡上都貼著地。

- `terrain.ts` 的 `TerrainBuilder.slope()` 已經支援，物理也會貼地走，不用重寫。要加的：
  - **上下坡速度**：`stepBody` 依地面斜率調最高速度：上坡 ×(1 − 0.35×坡度正弦)，下坡 ×1.1。30 度上坡約剩 82%。
  - **下坡貼地**：現在下坡超過 `SNAP_DOWN` 會變成一小段一小段掉。陡坡要用「這一步前進量 × 斜率」算貼地距離（現在的算法已接近，要測 30 度）。
  - **忍具撞地**：現在忍具不管地形，陡坡時會穿進坡裡。改成飛進地面以下就消失、冒火花（鼠火 I 照舊貼地跑、毛球 D 照舊彈）。
  - **敵人在坡上**：先確認每種地面敵人的腳底用 `groundAt`（程式裡看起來是，要逐隻跑一次確認）；野豬衝坡照樣衝。
  - **角色不傾斜**：越南大戰角色在坡上也是直立的，照舊直立，只有腳底貼地。
  - **地面帶美術**：先把現有地面帶在 30 度坡上的樣子截圖看；若看起來被拉歪，再請 Codex 生坡面專用的地面帶。

### 5.6 瀑布（決定 5）

**白話**：瀑布畫在角色後面、水會一直往下流；瀑布底下是水潭（掉下去扣一滴血，跟現在的坑一樣）；瀑布旁邊有一層一層的岩棚和岩壁可以往上爬。**水不會推你**，保持簡單。

- 畫法：Codex 生一條「可以上下無縫接」的瀑布水紋，程式每格往下捲（看起來就在流）；頂端水口一張、底部水花 4 格循環、水霧一張半透明往上飄。畫在中景之後、角色之前的背景層。
- 水潭：用現有的水坑（`ZoneDef.water`＋`terrain.json` 的 `water.s2_river`），第一關那座另生山溪色。
- 岩棚：單向平台新增 `look: 'rock'`（從下面跳得上去），間距 110～140 高，交錯左右，逼玩家用二段跳或蹬牆。
- 放哪：第一關（竹林和山賊寨之間的山溪）、第二關（河童川上游）；第三關換成工廠的「冷卻水道」鐵製瀑布（水紋染成鐵灰偏藍、岩棚換鐵架），不硬塞自然瀑布。

### 5.7 鏡頭上下捲不捲？

**白話**：現在鏡頭只會往右捲、不會上下動，畫面高 720、地面在 596。在不改鏡頭的前提下，一個畫面裡可以用的高低差大約 **420 像素**（最高站到約 y 260，頭剛好在分數欄下面；最低地面約 y 680）。這夠做「三層岩棚的瀑布」「兩段蹬牆的夾縫」，但做不出「往上爬好幾個畫面高」的大攀爬。

- **這份規劃預設：不改鏡頭**，所有新的上下段落都塞在一個畫面高內。這樣背景長卷、分數欄、敵人出場都不用動，風險最低。
- 要做「好幾個畫面高」的大攀爬，就要加「上下捲鏡頭」：背景每層要多畫上半部、敵人出場要改、分數欄位置要重算，大約多一整個階段的工，而且要重生背景上半部。這是第 13 節的問題一。

## 6. 關卡加長一倍（決定 6）

### 6.1 共通規則
- 每關 `length` 21,207 → 約 **42,000**；最後魔王鎖定點（`bosses[].final.at`）＝`length − 1280`。
- `timeLimit` 600 → **1000** 秒。
- 魔王不變，只是位置跟著往後挪；中魔王也不變。
- 敵人**只用現有的種類**（不加新敵人的美術），靠擺法和地形變化做出新鮮感：飛的（烏鴉、紙鶴、甲蟲砲台）放在攀爬段，地上的從坡頂衝下來。

## 7. 不要長篇教學（使用者補充）

- **拿掉**：三關 `hints`（例如第一關的「打爛木箱有東西吃」「坑：跑起來再跳過去」等 6 句）全部刪除；敵人「！」預兆保留（那是畫面語言，不是教學）。

- 自動玩卡住時，`tests/botsim.ts` 已會印「卡在 x=… 鏡頭…」，新段落卡住一樣看得到。

### 9.3 要加的測試
- `physics.test.ts`：二段跳最高約 300、只能一次、落地補回；貼牆下滑速度 ≤ 240；蹬牆離牆方向正確、0.15 秒鎖方向；攀爬沒有重力、到頂站上去；30 度上坡速度約 82%、下坡不會一段一段掉；實心方塊撞頭、側面擋住。
- `player` 相關：翻滾 0.04～0.34 秒內被碰不扣、之外會扣；翻滾穿過魔王；揮爪護身只擋身體碰撞不擋子彈；斜丟的方向與出手位置。
- 關卡檢查（`tests/stage*.test.ts` 加）：每一段新地形「跳得上去」——用程式算每一個高低差 ≤ 該段允許的動作能到的高度（沒有蹬牆的段落 ≤ 177＋餘裕，有二段跳的 ≤ 300，夾縫寬度在 200～320）；新村貓都放在拿得到的地方。
- 自動玩三關打得通（電腦版、手機版怪物圖各一次），破關時間 ≤ 540 秒。
- 「沒有教學字幕」測試：三關 `hints` 為空；按鍵一覽包含每個新動作。

## 10. 下載量與記憶體

網站是公開的 GitHub Pages，之前的目標：**進第一關前下載 < 40 MB、每關解碼後（圖片展開在記憶體裡的大小）< 300 MB。**

| 新增 | 下載 | 每關解碼 |
|---|---|---|
| 球球新動作 8 個 | 約 +4 MB（進第一關前就要載） | 約 +25 MB（全關共用） |
| 每關背景 +11 張 | 每關約 +4 MB | 中景一張 1530×720 約 4.4 MB，+8 張約 +35 MB；中遠景、最遠景約 +15 MB |
| 瀑布、攀爬、牆、平台 | 每關約 +1～2 MB | 約 +10 MB |
| 合計 | 第一關前約 +5 MB；每關 +5 MB | 每關約 +85 MB |

- 做法：背景改成**分兩半載**——進關只載前半段，鏡頭走過一半時在背景悄悄載後半段（現在已經有「分包背景載入」，照著延伸）。
- 每個階段結束都跑 `tools/mem_check.mjs`，超過就把手機版背景縮到 0.75 倍（手機螢幕小看不出來）。
- 階段零要先量出第一版現在的數字，才知道還剩多少空間。

## 11. 風險

| 風險 | 可能性 | 影響 | 怎麼降低 |
|---|---|---|---|
| 背景長卷插段接縫看得出來 | 高 | 畫面醜，違反「不倒退」 | 橋接圖＋切線羽化；退路用水霧、前景件蓋；每道接縫出放大圖給使用者看 |
| Vids 生不好貼牆、蹬牆、攀爬 | 中高 | 新動作沒有好看的動作圖就不能交 | 先 Codex 生姿勢圖再動；每支最多重生 3 次；真的不行就那個動作改成「用現有跳躍的某一格定住」並**明講給使用者裁決** |
| Vids 每日上限、需要使用者的 Chrome | 中 | 卡進度 | 階段一只生 4～6 支；其餘排在階段二、分兩天 |
| 物理加「實心方塊」弄壞舊關卡的手感 | 中 | 已調好的屋頂、升降台、魔王場地出問題 | 舊的手感測試（`physics.test.ts` 7 項）一律要過；三關自動玩前後比 |
| 翻滾、二段跳讓魔王戰太簡單 | 中 | 無聊 | 平衡報表看魔王戰時間；必要時魔王攻擊判定不吃翻滾無敵 |
| 關卡加長但敵人不變 → 拖 | 中 | 玩起來累 | 新段落以地形為主、敵人少兩成；超過 9 分鐘就砍 |
| 自動玩學新動作花很多工 | 中 | 測試跑不過就卡 | 新段落在關卡檔標好「夾縫」「攀爬」「岩棚」，自動玩照標記做 |
| 手機按鈕太擠 | 中 | 手機難玩 | 只加一顆「滾」；二段跳、蹬牆都用跳鍵；攀爬用方向盤 ↑ |
| 背景加圖超過記憶體 | 低中 | 手機閃退 | 分兩半載、手機版縮圖 |
| `export_sprites.py` 依賴爪破魔塔那邊的去綠幕程式 | 低 | 那邊搬動就不能轉動作 | 動手前確認路徑在；要搬就一起搬 |
